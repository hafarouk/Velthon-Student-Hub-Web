# VELTHON Student Hub

Public frontend hosted by **hafarouk** on GitHub Pages. Designed and developed by VELTHON Design and Development.

This repository contains public application code and branding only. Passwords, password verifiers, server secrets, authentication databases and study material must never be committed here. There is no public account registration. The owner provisions invited accounts in the separate authentication service.

## Access and privacy

The sign-in page and static frontend files are publicly downloadable, as required by public GitHub Pages hosting. Authentication and server session checks run in a separate HTTPS backend. GitHub Pages cannot execute PHP or protect static files with server-side passwords. The app does not use PHP.

Study material is stored in a per-user encrypted IndexedDB vault in the browser. It is not uploaded to this repository or synced between devices. The local vault requires the account password; first sign-in needs the authentication service. The Pages origin has its own workspace, so data from another site must be moved with the app's encrypted backup/restore.

Previously provisioned offline workspaces can be unlocked without the server. Revocation cannot reach a disconnected device. Protect the device and use a strong, unique account password. Anyone able to run a modified copy of the public frontend can alter their own local app; they do not gain another person's encrypted data or an authenticated server session.

Online sessions expire after one hour, are bound to the frontend origin, are revoked by online logout, and are invalidated when an account is disabled or its password verifier changes. Cross-site session tokens stay only in memory and are excluded from local vault records, backups, URLs and the service-worker cache. Third-party cookies are not required. Closing or reloading the page clears the in-memory token.

## Trial limitations

This is a trial, not a security certification. Optional document and local model tools download pinned libraries/models on first use from approved public services. Recognition may be inaccurate. Browser storage can be evicted; export encrypted backups. Physical iPad/Android stylus, speech and offline engine coverage still needs device testing. Email/cloud/calendar OAuth account integration is not implemented; local file and ICS imports are available.

## Security reports

Do not post credentials or private records in public issues. Contact the repository owner privately. See SECURITY.md for control details and remaining limitations.

## Web 0.4.2 — memory-conscious scans and explicit file destinations

Photos are decoded with native resize options where supported, capped to 1000/1400/1800 pixels on the longest edge, and previewed at a smaller size. File/object URLs replace full-resolution data-URL copies. Temporary image surfaces and idle model workers are released; OCR loads one selected language, supports cancellation, times out and terminates after the task. Optimized scan images are stored as separately encrypted binary records, and notes retain only identifiers. Full-resolution originals are offered for explicit saving rather than copied into note JSON. Existing inline photos remain readable. Handwriting reuses an offscreen drawing buffer and bounds undo history to reduce repeated allocation.

Save & cloud storage prepares one item at a time: passphrase-encrypted workspace/scan backup, notes, notebook PNG, optimized scan, original attachment, recording or any user-picked file. Local saving and the native Files/share picker are available according to browser/device capabilities. Direct Google Drive (drive.file) and OneDrive app-folder (Files.ReadWrite.AppFolder) uploads have separate explicit file/account consent. The deployment still needs owner Google/Microsoft app IDs, enabled APIs/permissions and user authorization before direct cloud/calendar connections work. No provider account was connected in development, no automatic cloud background sync is enabled, and device copies are not removed automatically. Larger files are directed to the native provider workflow; Google uploads over 5 MB use bounded resumable chunks. Cloud storage frees neither RAM nor device copies by itself; reduced image/model allocations address scan memory pressure.

Workspace backup version 2 includes optimized scan records and restores through the existing backup import, remaining compatible with version 1 imports. Original documents and recordings are exported individually. Backup scans are capped to 20 MB to avoid assembling an unbounded archive in memory. Users must retain their passphrase and a safe copy.

Validation adds a 12-megapixel photo reduced to at most 1 megapixel, encrypted binary photo round-trip, portable encrypted backup inspection, one-language OCR worker cleanup, offscreen canvas reuse across 100 paints, and explicit Google/OneDrive upload adapters against fixture APIs. Actual camera-process memory limits, cloud OAuth consent/permissions and media playback still require a physical device and configured provider accounts.

## 0.4.4 — recording, live transcript and temporary audio

Recording now asks for the situation (lecture hall, room meeting or online meeting), uses the system's active microphone automatically, and applies suitable gain/noise/echo settings. Online capture mixes the microphone and a browser-approved shared meeting audio track. Sharing is requested from the Record click; cancelled sharing, unsupported audio capture and a share with no audio track block the start rather than silently capturing only the local speaker. No screen video is recorded. Browser/OS permissions and hardware still determine what can be captured; native meeting apps and many mobile browsers cannot expose remote-call audio to a website. Users must stop capture when a call ends if sharing itself continues.

The local Whisper engine is loaded and verified before starting MediaRecorder. Initial model download is covered by recording consent and requires connected mode; cached engines work offline. Six-second audio segments feed live transcription and source-based note drafts. Manual notes are preserved with a separate suggested draft. A bounded speech backlog and bounded storage write queue stop capture with a visible explanation on overload/failure. Recognition remains a draft and may mishear words or fragment boundaries. This is not a guarantee of low latency or accuracy on every tablet.

Audio is written as separate AES-GCM encrypted chunks to the existing account vault every five seconds, instead of accumulating the entire class in memory until Stop. Capture can run up to four hours; the last unfinished chunk can be lost in an abrupt exit. Active-session checkpoints support recovery after interruption. Web Locks avoid simultaneous capture in two tabs where available. Slow storage or quota errors are reported. Whole-file transcription retry is limited to 20 minutes / 16 MB to avoid decoding a long recording into an enormous PCM buffer; long captures retain their incremental live transcript and can be downloaded.

A visible Temporary recording panel within each lecture provides native playback controls, download, transcript recovery and delete actions. Each new or imported audio session expires 15 minutes after Stop, sharing ends, or interruption. Subsequent transcript processing does not extend that deadline. Older saved audio is migrated into a new 15-minute window on first access in this version. Transcript and notes remain ordinary saved lecture data. Expired audio is rejected on every read and swept from encrypted storage while the app runs, including while the account is locked. Browsers cannot guarantee execution while fully closed/suspended: physical cleanup then runs at the next app launch/resume; this limitation is stated explicitly in consent. No audio/transcript is uploaded, and explicit user downloads are independent copies.

Authentication, authorized test-account restrictions, provider OAuth configuration, and the separate auth backend are unchanged.

Validation:
- `test-recording-v044.cjs`: incremental storage, stop-relative expiry, long active capture, concurrent read/write, interruption recovery, deletion, and no retention extension during final transcription.
- `test-capture-v044.cjs`: real bridge control flow with simulated browser APIs/recognizer: shared-audio requirement, recognizer readiness, per-situation constraints, mixed sources, live text before Stop, incremental writes, pause/resume and finalized metadata.
- `test-vault-retention-v044.cjs`: actual AES-GCM vault with fake-indexeddb 6.0.1 (install that test-only dependency and run with its node_modules on NODE_PATH); ciphertext, TTL access denial, cleanup while locked, account isolation and preservation of notes.

## v045 — account activity and consent receipts

Settings → Privacy & activity shows only the signed-in account’s records. The backend records successful/failed known-account sign-ins, sign-out and consent decisions. Minimal browser-reported activity is separately labelled; it is not evidence that a document was read or that a physical person performed an action.

Approval requires an unchecked checkbox and the typed displayed account name. The server stores the exact policy text, version, SHA-256 hash, account, scope, decision and authoritative received time, then HMAC-signs the receipt using a runtime-only key. This is an account acknowledgment, not verified identity or a certified electronic signature. Recording approvals apply to individual lecture references; provider approvals are separate from the provider’s OAuth screen. Existing browser-only approval flags are not converted into signed receipts.

Users can download individual JSON receipts, print them, verify their integrity online, export displayed history, load older pages and withdraw scopes. Withdrawal creates another record and stops future app use of the scope; it does not erase existing receipts or revoke separate provider permissions. History is retained up to 365 days. No passwords, tokens, full IP addresses, document/audio contents or search words are placed in this history. English policy text is explicitly versioned; the existing app interface languages remain available.

Offline decisions and actions are kept in the encrypted per-account vault and clearly marked pending until a later authenticated sync. Device timestamps are claims, distinct from server received time. First approval of a current workspace notice requires online sign-in. External-provider approval must be saved online before continuation. Security records and production signing keys never belong in this public repository. The backend source and SQL migration are maintained in the private source repository.

Validation: 23 backend tests cover authentication, user isolation, explicit approval, canonical text/hash, receipt tampering, idempotency, withdrawal, pagination, offline timestamps and retention. Browser consent checks use fictional accounts and a memory-only test service; no real user consent is accepted by automation.



## 0.4.6 — both-side capture and Online Group Study

External meeting recording is now a deliberate two-step flow: choose External online meeting, press Connect meeting sound and approve a tab/system audio source, then Record. Selecting a recording situation never opens the browser chooser. The recording button no longer opens another chooser. Microphone and meeting sound have separate level meters during recording. The browser's getDisplayMedia permission prompt cannot be removed: a static website cannot silently capture another app's speaker output. Only audio enters the recorder/transcriber; the browser-provided picture is ignored and never sent to peers or stored. OS and browser support still determine whether an external meeting source can expose audio.

Study now contains Online Group Study. Authorized students claim a unique study handle, create private groups, invite exact handles, accept/decline invitations and join voice-only WebRTC calls. The camera is never requested; getUserMedia uses video:false. Screen sharing is a separate explicit getDisplayMedia request with audio:false and can be stopped independently. A movable, resizable call panel minimizes to a small button so notes remain usable. Calls use the existing authenticated backend for membership and temporary signalling; call media stays on encrypted WebRTC connections between accepted participants. The backend logs explicit call consent and enforces accepted membership, peer ownership, same-group signalling and handle uniqueness. Signalling expires after five minutes. The existing account allowlist remains unchanged, so inviting a new person does not grant a public sign-up.

A new Online Group Study recorder situation captures the application's internal mixed audio directly, without screen sharing or a microphone chooser. It requires connected remote participants, explicit recording consent and announces the recorder to participants through call status. Saved audio still follows the existing 15-minute retention policy; transcript and notes remain saved. Recording consent distinguishes a local recording from live call media shared with participants.

Validation: updated capture-control tests pass for both external microphone+meeting mixing and internal group-stream recording with no screen chooser or new microphone acquisition. Audio/shape/asset regressions pass. The backend's 28 authentication, consent and group tests pass. Browser fixtures verified study handle/group/invitation/acceptance/consent UI and actual RTCPeerConnection offer/answer exchange between disposable participants with synthetic sources. The cloud browser gathered zero usable ICE candidates, including a standard relay test, so real two-way media and remote screen frames could not be verified in this environment. The app now reports missing network routes and blocks screen sharing/group recording before voice is connected. Direct calls use Google STUN. Reliable calling across restrictive NAT/firewall/proxy networks needs a TURN provider configured server-side with STUDY_ICE_SERVERS_JSON; no provider credentials or account are preconfigured. Actual two-device/network verification remains pending. No browser network protection was changed and no real user's account or microphone was used.

The concurrently released v045 Privacy & activity, signed consent receipts, provider consent wrappers and audit login hooks are retained.
