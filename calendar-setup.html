Connect the calendar behind your email

One-time setup for the Student Hub owner. Students then sign in through Google or Microsoft and grant read-only calendar consent. No email passwords, client secrets or provider tokens belong in GitHub.

Google / Gmail / Google Workspace

  1. In Google Cloud Console, use a project you administer. Enable the Google Calendar API.
  2. Configure Google Auth Platform branding/audience. In Testing mode, add the Google email addresses of your invited students as test users. School accounts may require administrator approval.
  3. Create an OAuth client ID of type Web application. Add the exact authorized JavaScript origin https://hafarouk.github.io. This site uses the Google popup token model, so it does not use a Google authorization-code callback.
  4. Add the read-only scope https://www.googleapis.com/auth/calendar.readonly.
  5. Copy the public client ID ending in .apps.googleusercontent.com into Calendars & email → Connection setup. Then tap Connect Google and approve access.

Official setup instructions · Google token model

Outlook / Microsoft 365

  1. In Microsoft Entra admin center, create an application registration in a directory you administer.
  2. Choose the supported account type that matches your students. To support work/school and personal Outlook accounts, choose organizational directories and personal Microsoft accounts. Organizational policies may limit consent.
  3. Add platform Single-page application (SPA) with this exact redirect URI: https://hafarouk.github.io/Velthon-Student-Hub-Web/calendar-oauth.html. The popup callback must remain on this site.
  4. Add Microsoft Graph delegated permission Calendars.ReadBasic. This reads event basics and calendar metadata. Do not configure application-wide permissions or client secrets. MSAL uses authorization code with PKCE.
  5. Copy the public Application (client) ID into Calendars & email → Connection setup. Tap Connect Outlook and approve calendar access.

Official app registration · Calendar permission reference

Optional direct cloud saving

For Google Drive, enable the Drive API in the same Google project and allow https://www.googleapis.com/auth/drive.file. The app requests that permission separately when the user explicitly saves a selected file. It creates app-owned files, rather than requesting full-drive access.

For OneDrive, add Microsoft Graph delegated permission Files.ReadWrite.AppFolder. Cloud upload requests that permission separately and saves in the application folder. Work/school administrator policies and account support can restrict it. The app never silently escalates to full-drive access.

No app registration is needed for Local saving or the device Files/share picker. iCloud, Google Drive and OneDrive visibility in that picker depend on the device and installed/signed-in providers. Background synchronization and automatic deletion from the device are not enabled.

Enable it for every invited student

Workspace setup is saved privately for the signed-in Student Hub user. To provide the same public application IDs to all students, the owner can add window.VELTHON_CALENDAR_APPS = {googleClientId: '…', microsoftClientId: '…'}; in the existing public hosting-config.js. These IDs identify the app; every student still signs in separately and consents with their own provider account. Leave either ID blank to omit that provider.

The frontend remains protected by the same Student Hub sign-in flow. Calendar tokens stay in session memory and are not included in workspace backups. Event copies are stored in the existing encrypted workspace. Refresh requires an open visible tab, Online mode, an active provider session and internet. This version does not fetch inbox messages or run a background server sync. Google events preserve event/calendar colours; Outlook preserves calendar colour. Disconnect removes cached events in this workspace and clears the session; Google also revokes its grant when an active token is available. Microsoft consent can be revoked in the account's application permissions.
